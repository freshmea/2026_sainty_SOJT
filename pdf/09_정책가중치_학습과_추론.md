## 2. 관측 세 개로 연속 행동 하나 만들기

07번 환경이 매 0.02초마다 `[현재각, 각속도, 목표각]`을 준다. 각도의 단위는 rad, 각속도는 rad/s다. 팔의 목표는 π/4 rad이고 시작 각도는 −0.1~0.1 rad다. 예를 들어 정책의 행동이 +0.4이면 환경은 +0.8 N·m를 가하고 물리 스텝 10개(각 0.002초)를 진행한다.

### 같은 관측을 두 신경망이 읽는 이유

| 신경망 | 입력과 층 구성 | 출력의 의미 |
|---|---|---|
| Actor · 행동 결정 | 3 → 32 → 32 → 1 | 정규분포의 평균 행동. 학습 시 탐색에 쓰는 표준편차도 학습한다. |
| Critic · 가치 추정 | 3 → 32 → 32 → 1 | 지금 상태에서 앞으로 받을 할인 누적 보상의 추정값 V(s) |

각 경로의 두 은닉층에는 `Tanh` 활성화를 사용한다. actor의 가중치는 3×32 + 32×32 + 32×1 = **1,152개**, 편향은 32 + 32 + 1 = **65개**다. critic도 같은 크기다. 탐색용 로그 표준편차 1개까지 포함하면 **전체 학습 파라미터는 2,435개**, ONNX로 내보내는 actor는 **1,217개**다.

```python
# train()의 모델 설정을 펼쳐 읽기
policy_kwargs = dict(
    net_arch=dict(pi=[32, 32], vf=[32, 32]),
    activation_fn=nn.Tanh,
    optimizer_class=torch.optim.Adam,
)
```

### 무엇을 잘해야 보상이 높아지는가

07번의 한 스텝 보상은 `−(각도 오차² + 0.01 × 각속도² + 0.001 × 토크²)`다. 목표에서 멀거나 너무 빠르게 움직이거나 큰 토크를 쓰면 누적 보상이 낮아진다. 성공 기준을 읽을 때는 에피소드 마지막 오차와 이동 중 오차를 함께 본다.

**확인 질문**　현재각이 같아도 목표를 향해 빠르게 가는 팔과 목표에서 멀어지는 팔에 같은 행동을 주어야 할까? 두 관측에서 달라지는 입력은 각속도다. 종료 조건은 관절 각도의 절댓값이 π를 넘는 실패와 200 제어 스텝(4초)의 시간 제한이다.

## 3. model.learn() 안에서 일어나는 일

`model.learn(total_timesteps=4096)`이 학습의 진입점이다. 환경 하나에서 128스텝씩 32번 데이터를 수집한다. 한 번 수집한 128개를 64개씩 나눠 10번 반복 학습하므로 기본 실행에서는 **640번의 Adam 갱신**이 일어난다.

1. **행동과 경험 수집**　actor의 정규분포에서 행동을 뽑는다. 환경에 보낼 때는 허용 범위 [−1, 1]로 자른다. SB3는 관측, 뽑은 행동, 기존 정책에서의 로그 확률, 보상, 가치 추정값 등을 rollout 버퍼에 기록한다.
2. **이점(advantage) 추정**　실제로 받은 보상과 critic의 가치 추정으로 각 행동이 예상보다 얼마나 좋았는지 계산한다. GAE는 이 추정에 여러 시점의 정보를 사용한다. 이 실습은 SB3 기본 할인율 0.99와 GAE 계수 0.95를 쓴다.
3. **PPO 손실 계산**　새 정책과 수집 당시 정책이 같은 행동에 부여하는 확률밀도의 비율을 구한다. `clip_range=0.2`는 정책 목적함수에서 이 비율을 0.8~1.2로 잘라 계산한 항과 원래 항을 비교하게 한다. critic은 목표 수익과 가치 예측의 오차로 학습한다.
4. **역전파와 갱신**　정책 손실과 가치 손실 등을 합친 뒤 기울기를 비우고 역전파한다. 기울기 크기를 제한하고 Adam이 파라미터를 갱신한다. 기본 학습률은 0.001이다.

```python
# SB3 2.7.0의 PPO.train()에 있는 갱신 순서
self.policy.optimizer.zero_grad()
loss.backward()
th.nn.utils.clip_grad_norm_(self.policy.parameters(), self.max_grad_norm)
self.policy.optimizer.step()
```

**손으로 계산하기**　정규화된 이점이 +1이고 확률밀도 비율이 1.35라면, 정책 목적함수는 두 후보 1.35와 1.20 중 작은 1.20을 택한다. 이미 확률이 크게 높아진 행동을 더 밀어주는 유인이 줄어든다. 이때의 1.20은 목적함수 계산에 쓰인 수치다. 모터 명령의 상한은 별도로 +1이다.

**코드에서 보기**　VS Code에서 `PPO`의 정의로 이동해 `PPO.train()` 안의 `loss.backward()`와 `self.policy.optimizer.step()`을 찾는다. 09번의 `train()`은 학습 절차를 구성하고, 이 두 줄은 라이브러리 내부에서 미니배치마다 실행된다. [SB3 2.7.0 PPO 소스](https://stable-baselines3.readthedocs.io/en/v2.7.0/_modules/stable_baselines3/ppo/ppo.html)

## 4. 저장한 정책으로 같은 팔을 다시 움직이기

`PPO.load()`로 ZIP을 복원한 뒤 `predict(obs, deterministic=True)`로 평가한다. 이어 `OnnxActor`가 복원한 특징 추출층, actor의 은닉층, 평균 행동 출력층을 받아 ONNX로 내보낸다. 마지막 `clamp(-1, 1)`도 그래프에 포함해 SB3의 결정적 행동과 같은 범위를 보장한다.

```python
# infer()가 제어 한 주기에 수행하는 추론
batch = session.run([output_name], {input_name: obs.reshape(1, 3)})[0]
action = batch[0]
```

Day 4의 `scripts/infer_policy.py`와 같이 세션을 한 번 열고 매 주기 관측을 새로 넣는다. 여기서는 입력 `observation`이 [1, 3], 출력 `action`이 [1, 1]이다. `batch[0]`으로 배치 축을 벗겨 07번 모터에 전달한다.

### 실제 실행에서 무엇이 달라졌는가

학습 시드는 7, 평가 시드는 11·22·33·44·55다. 각 정책을 같은 초기 상태 다섯 개에서 200스텝씩 평가했다. 평균 누적 보상은 클수록 좋고, 오차는 작을수록 좋다.

| 제어기 | 평균 누적 보상 | 전체 스텝 RMSE (rad) | 최종 평균 절대 오차 (rad) |
|---|---:|---:|---:|
| 행동 0 | −131.652060 | 0.81133 | 0.80966 |
| 학습 전 PPO | −159.881598 | 0.89409 | 0.98272 |
| ZIP 복원 후 SB3 | −5.717007 | 0.16084 | 0.00447 |
| ONNX Runtime | −5.717007 | 0.16084 | 0.00447 |

**결과 해석**　학습한 팔의 마지막 오차는 평균 약 0.26°였다. 움직이기 시작한 순간까지 포함한 RMSE는 0.16084 rad로 더 크다. 같은 관측 1,000개에서 SB3와 ONNX의 행동값 최대 절대 차이는 약 1.79×10⁻⁷이었다. 목표각은 모든 에피소드에서 45°였다.

**직접 해볼 실험**　4,096스텝 결과를 기록한 뒤 `train --steps 1024`로 다시 학습하고 `infer`를 실행한다. 두 실행의 RMSE와 최종 오차를 비교한다. 매 학습은 같은 시드로 새로 시작하고 같은 이름의 결과 파일을 갱신한다. 128의 배수가 아닌 스텝 수를 요청하면 SB3는 마지막 rollout을 채우므로 실제 학습량은 `09_arm_train.json`의 `training_steps`로 확인한다.
